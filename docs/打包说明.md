# 自动打包

双击项目根目录的 `build-release.bat`，等待出现 `SUCCESS`。

- 输出安装程序：`dist/installer/DeskIsle-Setup-<版本>-x64.exe`，以及同名的 `.sha256` 校验文件。
- 修改根目录 `VERSION` 可以改变下一次安装包的版本号；构建脚本会同步写入 `deskisle/__init__.py` 的 `__version__`（应用内更新靠它比较版本）。
- 自动运行测试，构建独立程序，并验证 EXE 的界面与原生右键菜单；任一步失败会停止。
- 首次需要本机安装 64 位 Python 3.10 或以上版本并可通过 `python` 命令运行。缺少的构建依赖和 Inno Setup 编译器会自动下载，首次构建需要联网。
- Inno Setup 以便携模式放在项目 `.tools/inno6`，不需要管理员权限。以后构建会复用它。
- 构建中间文件与日志放在 `work/package`。无需删除它们即可重复打包。
- 安装包自带运行依赖，使用者无需安装 Python。安装到当前用户目录，卸载保留 `%LOCALAPPDATA%/DeskIsle` 的布局数据。
- 安装前从系统托盘退出旧版 DeskIsle，以免同时运行旧进程。

手动指定工具或输出目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_release.ps1 -Python C:/Python313/python.exe -Iscc "C:/Program Files (x86)/Inno Setup 6/ISCC.exe" -OutputDir D:/Releases -NoOpen
```

构建脚本不会自动安装生成的安装包，也不会重启正在运行的 DeskIsle。

## 发布新版本（应用内更新）

已安装的桌屿会读取 GitHub 仓库 `narabias/DeskIsle` 的 **Latest release**。要让用户收到更新：

**方式一：推送标签，由 GitHub Actions 自动发布（推荐）**

1. 修改 `VERSION`（例如 `1.2.0`）并提交。
2. 推送同版本号的标签：`git tag v1.2.0`，`git push origin v1.2.0`。
3. `.github/workflows/build.yml` 会自动构建，并创建 Release、上传 `DeskIsle-Setup-1.2.0-x64.exe` 与 `.sha256`。
   标签与 `VERSION` 不一致时会直接报错，避免发布错版本。

**方式二：手动发布**

1. 修改 `VERSION`，运行 `build-release.bat`，得到：
   - `DeskIsle-Setup-1.2.0-x64.exe`
   - `DeskIsle-Setup-1.2.0-x64.exe.sha256`
2. 在 GitHub 新建 Release，标签写 `v1.2.0`（与 `VERSION` 一致），标题和说明会显示在应用的更新窗口中。
3. 把上面两个文件都作为附件上传，**不要改文件名**：应用只接受与标签版本一致的 `DeskIsle-Setup-<版本>-x64.exe`，
   并用 `.sha256` 文件（或 GitHub 自动提供的摘要）校验下载内容，没有校验值或校验失败都不会安装。
4. 发布为正式版（不要勾选 Pre-release，也不要停留在 Draft）。GitHub 的 `releases/latest` 接口不会返回预发布和草稿。

注意事项：

- 应用在启动约 15 秒后检查，之后约每 20 小时最多一次；用户也可在托盘菜单手动“检查更新”。
- 安装程序以静默模式运行，安装目录沿用上一次的位置，完成后自动重新打开桌屿；`%LOCALAPPDATA%\DeskIsle` 中的布局、设置、背景媒体与网页登录状态不会被修改。
- 版本比较支持 `1.2.0-beta.1` 这类预发布号：正式版 `1.2.0` 高于 `1.2.0-beta.1`。
- 仓库若改名或迁移，修改 `deskisle/updater.py` 中的 `REPO` 常量。
- 1.2 起安装包包含 Qt WebEngine（Chromium）与 Qt Multimedia，用于 HTML 动画、固定网页和背景视频，体积会比 1.1 明显增大。
