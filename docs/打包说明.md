## 一键打包

双击项目根目录的 `build-release.bat`，等待窗口里出现绿色的 `SUCCESS`。

- 安装程序输出到 `dist/installer/DeskIsle-Setup-<版本>-x64.exe`，旁边是同名的 `.sha256` 校验文件。
- 构建中间文件和每一步的日志都在 `work/package`（日志在 `work/package/logs`）。重复打包无需先删除它们。
- 构建脚本不会安装生成的安装包，也不会重启正在运行的桌屿。

**构建环境要求**

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 x64 |
| Python | 64 位 Python 3.10 – 3.13（推荐 3.13，与 GitHub Actions 相同），能在命令行用 `python` 运行；也可以用 `-Python` 指定 |
| 网络 | 首次构建需要联网：自动安装缺少的 Python 依赖并下载 Inno Setup 编译器 |
| 权限 | 不需要管理员权限 |

建议在干净的虚拟环境里构建，避免把开发机上无关的包打进去：

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt -r requirements-build.txt
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_release.ps1 -Python .venv\Scripts\python.exe
```

> 依赖使用 `PySide6-Essentials` + `PySide6-Addons`（6.12.0），**不要**安装完整的 `PySide6` 元包：
> 它会额外拉取约 400 MB 的 Qt WebEngine 与 Qt PDF。即使环境里装了，打包配置也会把它们排除，但会拖慢构建。

## 构建流程

`build-release.bat` 只是调用 `tools/build_release.ps1`。脚本按下面的顺序执行，**任何一步失败都会停止**，
并在窗口里显示该步日志的最后 30 行。

| 步骤 | 日志 | 做什么 |
|---|---|---|
| 版本号 | — | 读取根目录 `VERSION`（只接受 `2.0.1` 这种纯数字版本），写入 `deskisle/__init__.py` 的 `__version__`。应用内更新靠它比较版本 |
| 依赖 | `dependencies.log` | 试着导入 PySide6（QtQuick、QtMultimedia）、PyInstaller、Pillow、pywin32、lunar_python 与几个 WinRT 模块；缺任何一个就执行 `pip install -r requirements.txt -r requirements-build.txt` |
| 编译器 | — | 依次查找 `.tools/inno6/ISCC.exe`、`Program Files (x86)/Inno Setup 6`、`Program Files/Inno Setup 6`。都没有时从 GitHub 下载官方 Inno Setup 6.7.3，**校验发布者签名**（Pyrsys B.V.）后以便携模式装进项目的 `.tools/inno6`，以后复用 |
| 测试 | `tests.log` | `python -B -m unittest discover -s tests -v`（可用 `-SkipTests` 跳过） |
| 命令参考 | `guide.log` | `tools/gen_guide.py --check`：确认 `deskisle/agent/GUIDE.md` 末尾的命令参考与 `deskisle/agent/schema.py` 一致 |
| 图标 | `icon.log` | `tools/make_app_icon.py` 从 `packaging/icon-source.jpg` 生成 `packaging/DeskIsle.ico`、`DeskIsle.png` 与 `deskisle/assets/ui/app-icon.png` |
| 打包 | `bundle.log` | `PyInstaller packaging/DeskIsle.spec`，输出到 `work/package/dist/DeskIsle` |
| 验证 | `exe-check.json` | 检查三个 EXE、`Layer.qml`、图标数据 `glyphs.js`、`GUIDE.md`、`CHANGELOG.md` 是否都在；然后运行 `DeskIsle.exe --self-test`（最长 180 秒），报告必须是 `passed` |
| 安装程序 | `installer.log` | `ISCC /DAppVersion=<VERSION> /DBuildDir=... /DOutputDir=... packaging/installer.iss`，再写出 `.sha256` 文件（格式：`<SHA256>  <文件名>`） |

最后打开输出文件夹（`-NoOpen` 时不打开）。

## 构建参数

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_release.ps1 `
    -Python C:/Python313/python.exe `
    -Iscc "C:/Program Files (x86)/Inno Setup 6/ISCC.exe" `
    -OutputDir D:/Releases `
    -NoOpen -SkipTests
```

| 参数 | 作用 |
|---|---|
| `-Python` | 用于构建的 Python（默认 `python`） |
| `-Iscc` | Inno Setup 编译器 `ISCC.exe` 的路径（默认自动查找或下载） |
| `-OutputDir` | 安装程序的输出目录（默认 `dist/installer`） |
| `-NoOpen` | 完成后不打开输出文件夹 |
| `-SkipTests` | 跳过单元测试。**成品 EXE 的自检始终会运行**，所以跳过测试也不会产出打不开的安装包 |

## 安装包里有什么

PyInstaller 采用 one-folder 模式，三个程序共用一个 `_internal` 文件夹：

```
DeskIsle/
├─ DeskIsle.exe            主程序（无控制台窗口；守护进程 --watchdog 与自检 --self-test 也由它运行）
├─ deskisle-cli.exe        命令行工具与 MCP 服务器（控制台程序，不加载 Qt，启动很快）
├─ DeskIsleShellMenu.exe   显示 Windows 原生右键菜单的辅助进程（第三方 Shell 扩展卡住或崩溃时不影响主程序）
└─ _internal/
   ├─ deskisle/qml/        Qt Quick 界面、shaders/*.qsb、glyphs.js（图标）、LICENSE-TABLER.txt
   ├─ deskisle/assets/     应用图标、演示壁纸与 HTML 动画、WebView2Loader.dll（x64 / x86 / arm64）
   ├─ deskisle/agent/GUIDE.md   给 AI 助手读的说明（“设置 → AI 与扩展 → 说明文档”打开它）
   ├─ docs/                使用说明、打包说明与截图（“设置 → 关于 → 使用说明”打开它）
   ├─ README.md  CHANGELOG.md  THIRD-PARTY-NOTICES.md  LICENSE  VERSION
   └─ PySide6/ …           Qt 运行库（动态链接，可替换，见 THIRD-PARTY-NOTICES.md）
```

`packaging/DeskIsle.spec` 里几个需要知道的地方：

- **数据文件保持源码目录结构**（`deskisle/qml`、`deskisle/assets` …），因为代码按自己所在的位置查找它们。
  新增资源文件夹时记得加进 `datas`。
- **服务按名字动态导入**，PyInstaller 看不到，所以在 `SERVICES` 中列出；新增服务模块时一并加上。
  WinRT 命名空间、`lunar_python`、`win32com.shell` 也在 `hiddenimports` 里显式列出。
- **精简 Qt**：`excludes` 排除 WebEngine、3D、图表、定位、PDF 等 Python 模块；PyInstaller 的 QtQml 钩子会复制
  Qt 自带的全部 QML 模块，`UNUSED_QML` / `UNUSED_LIBS` 再把用不到的 QML 模块和它们拉进来的 DLL 删掉。
  桌屿的 QML 只导入 `QtQuick`、`QtQuick.Effects`、`QtQuick.Shapes`、`QtQuick.Window` 与 `QtMultimedia`。
  **如果在 QML 里新增了别的 `import`，先确认它不在这两个列表里**，否则自检会报“QML does not compile”。
- `deskisle-cli.exe` 与 `DeskIsleShellMenu.exe` 各自排除 PySide6，只带纯 Python 代码。
- 打包时把 `PATH` 限制为 Python 目录与 `System32`，防止开发工具注入的 ICU / OpenSSL DLL 被误打进去
  （Qt 使用 Windows 自带的 ICU，混入其他版本会导致启动失败）。

## 安装程序的行为

安装脚本是 `packaging/installer.iss`（Inno Setup 6，简体中文界面 `packaging/ChineseSimplified.isl`）。

- **按用户安装、不需要管理员权限**，默认装到 `%LOCALAPPDATA%\Programs\DeskIsle`；仅限 x64、Windows 10 及以上。
- 可选任务：
  - “创建桌面快捷方式”（默认不勾选）；
  - “把命令行工具 deskisle-cli 加入 PATH”——写入**当前用户**的 PATH，卸载时移除。
    此任务只在安装向导中提供，**静默安装与应用内更新永远不会修改 PATH**。
- **覆盖安装前删除旧的 `{app}\_internal`**：2.0 换成了 Qt Quick 运行库，这样不会有 1.x 的 Qt 插件或 DLL 残留。
- 如果用户之前开启了开机启动（`HKCU\…\Run` 中的 `DeskIsle` 值），安装时会把它更新为新的程序路径；
  命令行加 `/SKIPSTARTUPMIGRATION=1` 可跳过这一步。
- 安装时若桌屿正在运行，安装程序会请求关闭它（`CloseApplications`）；也可以先从托盘菜单“退出桌屿”。
- 完成页有“启动桌屿 DeskIsle”复选框；应用内更新（静默安装并带 `/DESKISLERELAUNCH=1`）完成后会自动重新打开桌屿。
- 再次安装或更新时沿用上一次的安装位置与任务选择。
- **卸载不会删除用户数据**：`%LOCALAPPDATA%\DeskIsle` 里的布局（`state.json`）、快照（`snapshots/`）、
  背景媒体（`media/`）、导入的字体（`fonts/`）、自定义文件夹（`custom/`）、网页登录状态（`web/`）与日志都会保留。
  要彻底清除，卸载后手动删除这个文件夹。卸载会移除指向本安装位置的开机启动项与 PATH 条目。
- 安装程序本身从不读写用户数据。1.x 布局在**首次启动 2.0 时**由程序自动备份为快照
  “升级到2.0之前的布局”后再迁移。

批量部署时可以静默安装：

```bat
DeskIsle-Setup-2.0.0-x64.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /TASKS="desktopicon"
```

可加 `/DIR="D:\Apps\DeskIsle"` 指定位置。静默安装后不会自动启动桌屿。

## 自检（--self-test）

```bat
DeskIsle.exe --self-test D:\check\report.json
```

源码运行时用 `python main.py --self-test report.json`。自检在**隔离的临时数据目录**里以演示模式运行完整的程序，
使用离屏渲染和独立的命名管道，**不会碰到真实桌面、你的布局，也不会影响正在运行的桌屿**。它检查：

- 打包内容：QML 目录、编译好的着色器（`*.qsb`）、`GUIDE.md`、应用图标、`WebView2Loader.dll`；
  `lunar_python`、QtMultimedia、QtQuick、QtNetwork、WinRT（正在播放、定位）、`win32com.shell` 都能导入；
- 每个 QML 文件都能编译，图层、灵动岛、设置窗口的所有页面与菜单在构建时没有 JavaScript 错误，桌面操作端到端可用；
- AI 接口：通过命名管道调用 `island.list`、`desk.state`（与 `deskisle-cli`、MCP 走同一条路）；
- 原生右键菜单辅助进程能列出 Windows 菜单；`deskisle-cli.exe --version` 能运行；布局能保存再读回。

结果写在 `report.json`（`status` 为 `passed` 或 `failed`，失败时 `error` 里有完整的调用栈；另有 `version`、
`qml_compiled`、`modules`、`webview2`、`services`、`settings`、`agent`、`native_menu`、`cli_exe`、
`qml_warnings` 等字段），旁边还有两张截图 `report.png`（桌面）与 `report-settings.png`（设置窗口）。
通过时退出码为 0。构建脚本把它们写在 `work/package/logs/exe-check.*`。

## 发布新版本（应用内更新）

已安装的桌屿会读取 GitHub 仓库 `narabias/DeskIsle` 的 **Latest release**（仓库改名或迁移时修改
`deskisle/updater.py` 的 `REPO` 常量）。

**发版前**

1. 修改根目录 `VERSION`（例如 `2.0.1`）。构建脚本会自动同步 `deskisle/__init__.py`；
   `packaging/installer.iss` 里的 `AppVersion` 只是直接用 ISCC 编译时的默认值，构建脚本会传入 `VERSION` 覆盖它。
2. 在 `CHANGELOG.md` 顶部写上这一版的变化（它随安装包分发，可在“设置 → 关于 → 更新日志”打开）。
3. 提交改动。

**方式一：推送标签，由 GitHub Actions 自动发布（推荐）**

```bash
git tag v2.0.1
git push origin v2.0.1
```

`.github/workflows/build.yml` 会在 `windows-latest` 上用 Python 3.13 构建（通过 Chocolatey 安装 Inno Setup），
上传构建产物（保留 30 天），并创建 Release、附上 `DeskIsle-Setup-2.0.1-x64.exe` 与 `.sha256`，
发布说明由 GitHub 根据提交自动生成。**标签与 `VERSION` 不一致时直接报错**，避免发布错版本。
也可以在 Actions 页面手动运行该工作流：不填版本号只构建产物，填 `v2.0.1` 则同时发布。

**方式二：手动发布**

1. 运行 `build-release.bat`，得到 `DeskIsle-Setup-2.0.1-x64.exe` 和 `DeskIsle-Setup-2.0.1-x64.exe.sha256`。
2. 在 GitHub 新建 Release，标签写 `v2.0.1`（与 `VERSION` 一致）。标题和说明会显示在应用的更新提示里。
3. 把两个文件都作为附件上传，**不要改文件名**。
4. 发布为正式版：不要勾选 Pre-release，也不要停留在 Draft——GitHub 的 `releases/latest` 接口不返回预发布和草稿。

**应用这一端会做什么**

- 启动约 15 秒后检查一次，之后约每 20 小时最多一次（可在“设置 → 关于 → 自动检查更新”关闭）；
  也可以在托盘菜单或“设置 → 关于 → 软件更新”手动“检查更新”。
- 只接受与标签版本一致的 `DeskIsle-Setup-<版本>-x64.exe`，用 `.sha256` 附件（或 GitHub 为附件提供的摘要）
  校验下载内容；**没有校验值或校验失败都不会安装**。只从 GitHub 的域名下载，下载停滞 60 秒会中止。
  安装包临时保存在 `%TEMP%\DeskIsle-Update`。
- 安装前自动保存一份布局快照“更新前自动备份”，然后以
  `/SILENT /SUPPRESSMSGBOXES /NORESTART /SP- /CLOSEAPPLICATIONS /DESKISLERELAUNCH=1` 运行安装程序：
  沿用原来的安装位置，完成后自动重新打开桌屿，用户数据不受影响。
- 版本比较能识别 `2.1.0-beta.1` 这类预发布号（正式版 `2.1.0` 高于它），但构建脚本的 `VERSION` 只接受纯数字版本，
  而且 Latest release 不会是预发布，所以测试版需要手动分发安装包。

## WebView2 运行时

网页岛与本地 HTML 动画使用系统自带的 Microsoft Edge WebView2，安装包**不包含 Chromium**，
只附带约 200 KB 的 `WebView2Loader.dll`（`deskisle/assets/webview2/<x64|x86|arm64>/`，许可见同目录 `LICENSE.txt`）。

- 目标电脑需要 WebView2 运行时（Windows 11 与绝大多数 Windows 10 已自带）。没有时网页岛显示下载链接，其他功能不受影响。
  如需随安装包分发，可在 `installer.iss` 中调用微软的常青版引导程序 `MicrosoftEdgeWebview2Setup.exe /silent /install`。
- 合成模式 / 窗口模式由程序在运行时决定（“设置 → 桌面 → 网页显示方式”），与打包无关。
- 自检报告的 `webview2` 字段给出运行时状态（`ok`、`no-runtime` …）。

## 代码签名（可选）

未签名的安装包在首次下载运行时可能出现 SmartScreen 的“Windows 已保护你的电脑”，需要点“更多信息 → 仍要运行”。
如果有代码签名证书，可以用 `signtool` 给三个 EXE 和安装程序签名（Inno Setup 的 `SignTool` 指令能在编译时自动签名卸载程序与安装程序）。
应用内更新只校验 SHA-256，不依赖签名。

## 应用图标的授权

应用图标由 `python tools/make_app_icon.py` 从 `packaging/icon-source.jpg` 生成。**公开发布或商用前，请确认这张插画的使用授权**；
如需替换，运行 `python tools/make_app_icon.py <图片> --box X0 Y0 X1 Y1`（裁切框为图片像素坐标）重新生成，详见
`THIRD-PARTY-NOTICES.md`。

## 常见构建问题

| 现象 | 处理 |
|---|---|
| `python` 不是内部或外部命令 | 安装 Python 时勾选“Add python.exe to PATH”，或用 `-Python` 指定完整路径 |
| `[tests] failed` | 查看 `work/package/logs/tests.log`；只想先试打包可加 `-SkipTests` |
| `[guide] failed` | 改了 `deskisle/agent/schema.py` 却没更新说明：运行 `python tools/gen_guide.py` 重新生成命令参考并提交 |
| `The bundle is incomplete: …` | spec 的 `datas` 漏了新文件夹，或文件被 `UNUSED_QML` / `UNUSED_LIBS` 误删 |
| `EXE self-test failed` / `timed out` | 打开 `work/package/logs/exe-check.json` 看 `error`，再看两张截图；常见原因是新增的 QML `import` 被精简掉、新服务没写进 `SERVICES`、或杀毒软件拦截 |
| 下载 Inno Setup 失败 | 手动安装 Inno Setup 6 后重试，或用 `-Iscc` 指定 `ISCC.exe` |
| 杀毒软件误报 PyInstaller 生成的 EXE | 把项目的 `work` 文件夹加入排除列表后重新构建；正式发布建议签名 |
| 安装包体积突然变大 | 检查构建环境是否装了完整的 `PySide6` 元包或其他大型库，并确认 spec 的 `excludes` 仍然生效 |

> macOS / Linux 不提供安装包。`packaging/DeskIsle.spec` 只用于 Windows；在其他系统上可以用
> `python main.py --demo` 以普通窗口试用演示布局（网页岛需要额外安装 `PySide6-WebEngine`）。
